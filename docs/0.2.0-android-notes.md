# dsh 0.2.0-rc.2 的 Android/Termux 适配说明

面向 `@deepseek-ai/dsh@0.2.0-rc.2`。0.2.0 是大重构（依赖包 194 → 286：
`dsh-client-web` 拆成数十个 `dsh-client-ui-*`，`dsh-host-apiproxy` 拆成
`dsh-api-*-controller`，新增会话格式 v0→v4 迁移链），因此 rc.6/rc.7 时代的补丁
锚点多数已失效，需要下面这套新脚本。

## 一、0.2.0 在 Android 上的两个硬阻塞

上游只发布 darwin / linux(gnu|musl) / win32 的原生包与平台支持，Android 完全不在
矩阵内。两个阻塞都不是配置问题，而是启动/写入路径上的硬门禁：

| 阻塞 | 现象 | 原因 | 解法 |
|---|---|---|---|
| `node-addon-require-builtin` 无原生绑定 | 启动即 `host preparation failed` | 上游 `optionalDependencies` 无 android-arm64（npm E404），发布版不含源码（fail closed） | `patch-dsh-android-0.2.js` 用纯 JS shim 顶替：dsh 只用它取 Node 内部模块，而包装脚本已带 `--expose-internals`，`require('internal/...')` 等价可得 |
| `flock` 不支持 android | web 能启动，但**一发消息就写不了会话** | `node-addon-system/lib/flock.js` 门禁仅放行 linux/darwin，且无 android 平台包 | `build-flock-android.sh` 用该包自带的 `src/flock.c` 本地编译（纯 C Node-API 单文件），并放行门禁 |

`flock(2)` 在本机实测**可用**（SELinux 只挡了 `link(2)`，没挡 `flock(2)`），
锁语义完整：获取成功 / 争用返回 `EAGAIN` / 关闭即释放。

## 二、脚本

```bash
# 1) 旁路安装（不覆盖在用安装）
CFLAGS="-target aarch64-linux-android30 -I$PREFIX/include" \
CXXFLAGS="-target aarch64-linux-android30 -I$PREFIX/include" \
  npm install -g --prefix ~/dsh-stage \
  --allow-scripts=@deepseek-ai/dsh-subprocess-local,koffi,node-pty,@google/genai,protobufjs \
  @deepseek-ai/dsh@0.2.0-rc.2

# 2) Android 补丁（幂等）
node patches/patch-dsh-android-0.2.js --install ~/dsh-stage/lib/node_modules/@deepseek-ai/dsh

# 3) 编译 flock 绑定（幂等，自带自检）
bash patches/build-flock-android.sh ~/dsh-stage/lib/node_modules/@deepseek-ai/dsh

# 4) 前端移动端适配
bash apply-frontend.sh ~/dsh-stage/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-web-frontend/dist/index.html

# 5) 切换（先 --check 再执行）
bash ~/dsh/upgrade-to-0.2.0.sh --check
bash ~/dsh/upgrade-to-0.2.0.sh
```

回滚：`bash ~/dsh/rollback-dsh.sh`（会一并还原 rc.6 可读的配置格式，`sessions/` 不动）。

## 三、`patch-dsh-android-0.2.js` 覆盖的 5 项

1. `require-builtin` 纯 JS shim（见上）。
2. `dsh-session-persistence-jsonl` 两处硬链接发布：
   - `materializePosix` → `rename`（临时文件随发布被消耗，后续 `rm` 均带 `force:true`）；
   - `publishCurrentExclusive` → `copyFile(COPYFILE_EXCL)`（必须保留 no-replace 的
     `EEXIST` 语义）。
   - ⚠️ `link` **必须保留在 import 中**：0.2.0 的 `defaultFileSystem` 依赖注入默认
     对象以裸 `link,` 引用它，删掉会 `ReferenceError: link is not defined`。
3. `dsh-attachment-local`：两处发布改为 `copyFile(..., COPYFILE_EXCL)`。
   注意语义与 rc 时代不同 —— `publishImmutableAlias` 的 `source` 是既有内容寻址
   对象必须保留，**不能用 rename**；`COPYFILE_EXCL` 恰好保持与 `link` 相同的
   `EEXIST` 竞态语义。另加祖先目录遍历容忍 `EACCES/EPERM/ENOSYS`。
4. `dsh-fs-local`：`write` 工具新建文件的 no-replace 发布在 `link` 被拒时回退到
   `O_CREAT|O_EXCL` 占位 + `rename` 填充。
5. `dsh-client-ui-conversation`：作曲栏「普通回车=换行，Ctrl/Cmd+Enter=发送」。
   0.2.0 键盘处理已重构到 Lexical `registerCommand` 的 Enter 处理器（rc 时代的
   `keyboard.arbitrate` / textarea 路径不复存在），返回 `false` 即交回 Lexical
   默认行为插入换行。

## 四、0.2.0 不再需要的补丁

- **`dsh-subprocess-local` 的 `android → linux`**：`LinuxProcessInspector` 已删除，
  新的 `selectContainmentMode()` 在 Android 上返回 `"fallback"`（普通 spawn + 一条
  警告），属优雅降级。

## 五、`patches/0*.patch` 那 5 个性能补丁已全部不适用

| 补丁 | 状态 |
|---|---|
| 01-apiproxy-history-slim | 载体包 `dsh-host-apiproxy` 在 0.2.0 已不存在 |
| 02-runtime-incremental-resync | 载体包 `dsh-client-runtime` 已不存在 |
| 03-connection-history-schema | 目标在，锚点不匹配 |
| 04-frontend-static-cache | 目标在，锚点不匹配 |
| 05-client-modules-cache | 目标在，锚点不匹配 |

需要按 0.2.0 的新文件布局重新适配（属独立优化工作，不影响升级可用性）。

## 六、其他注意

- **`DSH_HOME` 是唯一的配置隔离开关**（`$DSH_HOME/profiles`、`$DSH_HOME/.credentials.yaml`）。
  拿新版本试跑时**务必**显式设置，否则会直接迁移在用配置。
- 0.2.0 首次启动会把 `settings.yaml` 迁移为 `settings.yaml.imported`，并把
  `.credentials.yaml` 升级为新 schema（`version: 1 / refs:`）。**rc.6 的解析器读不了
  新 schema**，所以回滚必须还原这两个文件（`rollback-dsh.sh` 已处理）。
- 还会需要：`@img/sharp-wasm32@<sharp 版本>` + `@emnapi/runtime`（android-arm64 无
  sharp 原生预编译）。
- 升级 dsh 或重装后，`patch-dsh-android-0.2.js` 与 `build-flock-android.sh` 都要重跑。
